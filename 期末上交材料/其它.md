## 四、技术卡点与解决方案实录

### 卡点 1：Morton 编码类型转换溢出
- **现象**：坐标超过 1024 时编码异常，寻路结果错误
- **原因**：`SplitBy3` 函数中对 int 的位操作使用了 32 位整数，高坐标数据被截断
- **解决**：将中间变量改为 `ulong`，确保位操作在 64 位空间进行
- **提交**：`89c0eba` `修复 MortonCode.Decode ulong&int 类型不匹配`

### 卡点 2：死亡动画播放时序
- **现象**：技能击杀目标后模型立刻消失，看不到死亡动画
- **原因**：伤害计算 → 死亡判定 → 销毁模型在同步代码中顺序执行，没有等待动画
- **解决**：
  1. 第一次尝试：硬编码延迟 1.5 秒（不灵活，提交 `bde2432`）
  2. 第二次迭代：用 Animator.GetCurrentAnimatorClipInfo 获取实际动画长度（提交 `bde2432`）
  3. 第三次迭代：通过 onComplete 回调机制，动画播完后再销毁（提交 `7f0bf7c`）
  4. 最终版本：死亡动画配置移入 ViewConfig ScriptableObject 统一管理（提交 `f19c4f1`）
- **启示**：硬编码延迟是技术债务，异步回调 + 配置驱动才是正确方案

### 卡点 3：UI 面板全屏遮挡
- **现象**：打开某个 UI 面板后，场景中的所有点击输入都失效
- **原因**：`OpenPanel` 中调用了 `ResetRectTransform`，将面板的 RectTransform 拉伸至全屏，阻挡了所有射线
- **解决**：移除不必要的 `ResetRectTransform` 调用，面板只覆盖其实际需要的区域
- **提交**：`3045307` `fix: remove ResetRectTransform call from OpenPanel`

### 卡点 4：AI 任务优先级双重计算
- **现象**：AI 的行为决策偏向性异常，某些任务被重复加权
- **原因**：旧版代码的 `BasePriority` 计算逻辑残留在新代码中，与新的 `Utility` 评分重复
- **解决**：逐步追踪 AIDirector 中的每项 task 优先级计算链路，删除残留的双重计算
- **提交**：`a902d9a` `修复 AIDirector 中所有 task BasePriority 与 utility 重复计算`

## 五、自评与反思

### 做得好的方面
1. **架构前期投入**：在编码大规模展开前完成了技术选型调研（Deepresearch.md）和架构规划（立项说明.md），避免了后期大幅返工
2. **持续重构文化**：对命名空间、性能瓶颈等技术债务不拖延，主动安排专项重构周（第 6 周）
3. **Commit 规范**：从项目中期开始坚持 Conventional Commits 风格，方便快速定位变更历史
4. **AI 工具的务实使用**：没有盲目信任 AI 生成的代码，每段代码都经过人工审查和编译验证

### 需要改进的方面
1. **测试缺失**：整个项目没有建立自动化测试框架，所有测试依赖手动 Play Mode 测试。核心算法（A*、伤害计算、AI 评分）应当有 EditMode 单元测试
2. **文档异步**：部分关键逻辑的文档分散在代码注释中，缺少集中索引。后续应建立按模块索引的开发者文档
3. **性能基准缺乏**：没有建立性能回归测试（如 AI 决策耗时基准），无法自动检测性能劣化
4. **可视化工具欠缺**：技能配置目前完全依赖 Inspector 手填字段，容易出错且效率低

### 下一步学习计划
1. Unity Test Framework — 为核心算法添加单元测试
2. Unity DOTS/ECS — 探索数据导向架构，解决大规模单位的性能瓶颈
3. Unity Netcode for GameObjects — 为游戏添加多人联机功能
4. CI/CD 实践 — 搭建 GitHub Actions + Unity 自动化构建管线
