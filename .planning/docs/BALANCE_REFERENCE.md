> 最后更新: 2026-07-24  
> 适用范围: 角色属性、敌人属性、技能伤害、Buff、Relic、升星成长

## 一、数值设计哲学

### 1.1 加法/定值优先

本游戏的数值体系以 **定值加减法** 为基础，**克制使用百分比**。

| 原则 | 说明 |
|---|---|
| **Buff 以定值为主** | 力量 Buff = ATK +1，而非 ATK +10% |
| **DEF/RES 作用在伤害上** | 物理 `ATK - DEF`，魔法 `ATK - RES/2` |
| **百分比仅在特殊场合出现** | 例如"HP 低于 50% 时触发"的条件判定，或稀有 Relic 效果 |
| **避免乘法级联** | 当百分比 Buff 和定值 Buff 叠加时，应明确运算顺序（现在：先定值后百分比） |

### 1.2 全程损耗（无战间回血）

玩家在一局完整游戏中经历多场战斗，**战斗间隙不会自动回血**。这意味着：

- 每场战斗的 **单兵损耗** 必须可控
- 前排（坦克/战士）应该承受大部分伤害，使后排得以保留
- 治疗技能是珍贵的战略资源（消耗 MP，且 MP 恢复有限）
- 回复类 Relic/被动在长流程中价值极高

### 1.3 小数字、高可读性

- Lv1 角色 HP 范围: **18 ~ 34**
- Lv1 角色 ATK 范围: **3 ~ 10**
- 伤害数字全部在个位/十位数，玩家可心算
- 每一点 DEF 差异都有感觉，每一点 ATK 增加都有意义

## 二、行动点系统 (AP)

### 2.1 设计目标

每回合移动一次是硬性规定，**行动可用次数则由 AP 决定**。默认 1 AP = 1 次技能/攻击。

> 未来目标：通过 Buff、Relic、技能效果增加 AP，实现"一回合多次行动"甚至极限流派。

### 2.2 当前状态

```csharp
// MapUnit.OnTurnStart()
actionPoints++;          // 默认+1
// MapUnit.MarkAsActionDone()
actionPoints = 0;        // 使用技能后归零
// TurnManager.TryEndCurrentUnitTurn()
if (actionPoints <= 0 || IsActionDone)
    EndCurrentUnitTurn();
```

**当前行为：** 固定 1移动 + 1行动。AP 框架已搭好，但 `MarkAsActionDone()` 直接置零忽略了额外 AP。

### 2.3 目标实现

| 操作 | AP 变化 |
|---|---|
| 回合开始 | `actionPoints = maxAP`（默认 1） |
| 使用技能/普攻 | `actionPoints--` |
| 移动 | 不消耗 AP（一回合最多移动一次） |
| AP 降至 0 | 回合自动结束 |
| Buff/Relic 加 AP | `actionPoints++` 或 `maxAP++` |

**代码改造要点：**
1. 新增 `maxActionPoints` 属性（默认 1），Buff/Relic 可修改
2. `ResetTurnState()` 设置 `actionPoints = maxActionPoints`
3. `MarkAsActionDone()` 改为 `actionPoints = max(0, actionPoints - 1)`
4. 移除 `OnTurnStart()` 中的 `actionPoints++`（避免双重赋值）
5. 新增 `GainActionPoint(int amount)` 方法供技能/Buff 调用

### 2.4 AP 系统的设计边界

| 限制 | 说明 |
|---|---|
| 最多行动次数 | 每回合上限建议 3-4 次（防止"无限流"失控） |
| AP 来源 | 特定被动技能、Relic、精英技能 |
| 额外 AP 的代价 | 通常以 MP 或 HP 交换，而非免费获得 |
| 一回合一次的技能 | 可标注"本回合仅可使用一次"标签 |

## 三、核心公式全集

### 3.1 伤害公式

```
技能原始伤害 = (caster.ATK + FlatBonus) × Multiplier + Constant
```

> NormalAttack: Multiplier=1, FlatBonus=0, Constant=0 → 纯粹 ATK 值

#### 物理伤害

```
finalDamage = max(0, rawDamage - target.DEF)
```

- DEF 可直接免疫物理（ATK ≤ DEF → 0 伤害）
- 高 DEF 单位对低 ATK 单位天然克制

#### 魔法伤害

```
finalDamage = max(1, rawDamage - target.RES / 2)
```

- **保底 1 点伤害**：魔法永远不会完全免疫
- RES 每 2 点 = 减伤 1 点（与物理 DEF 类似但效率减半）
- 魔法克制高 DEF 低 RES 单位（坦克的弱点）

#### 设计意图：物理 vs 魔法的体感差异

| | 物理 | 魔法 |
|---|---|---|
| 公式 | `ATK - DEF` | `ATK - RES/2`（保底1） |
| 可被完全免疫 | ✓ (DEF ≥ ATK) | ✗（永远打1+） |
| 典型持有者 | 战士、Archer、近战怪 | 法师、精英技能、环境 |
| 定位 | 高 DEF 是硬克制 | 高 RES 降低但无法杜绝 |

#### 真实/元素伤害

- **True Damage**: `damage = rawDamage`（无视 DEF/RES，不进入 CombatCalculator 的防御阶段）
- **Fire / Poison / Ice**: 与 True 同一路径，无防御减免
  - 通常附带 DOT（每回合 N 点，持续 T 回合）或额外效果
  - DOT 伤害不走 CombatCalculator，直接扣血

#### 治疗

```
heal = baseHeal（独立配置，不依赖 caster.ATK）
```

- 治疗技能直接设置 Effect Type = Heal，Constant = 治疗量
- 示例：Heal 技能 `Constant = 6` → 回复 6 HP
- 治疗可以被 Buff（如"治疗效果 +2"）增强，后续通过 `OnHeal` 事件处理

### 3.2 CombatCalculator 流水线（代码现状）

```
阶段0：秒杀指令检查（CommandConfig.playerOneShotKill）
阶段1：攻击者输出修正 (OnOutgoingDamage)
阶段2：防御/抗性减免
  - 物理: finalDamage = max(0, finalDamage - DEF)
  - 魔法: finalDamage *= (1 - RES/100)   ← 【待改造为减法公式】
阶段3：防御者受击修正 (OnIncomingDamage)
最终: damage = max(0, finalDamage)
```

> **待办：** 魔法公式需要从百分比 `*(1-RES/100)` 改为 `max(1, damage-RES/2)`。当前 RES 统一 0~5 区间，百分比下完全无效果。

### 3.3 行动值/速度公式

```
CurrentActionValue = 10000 / Speed
```

- Speed 越高 → AV 越低 → 行动越优先
- AV 相同时，Speed 高的先行动

| Speed | AV | 每 100 行动单位的"轮数" |
|-------|-----|---|
| 65 (Tank) | 154 | 0.65 |
| 85 (Warrior) | 118 | 0.85 |
| 100 (Archer) | 100 | 1.00 |
| 110 | 91 | 1.10 |

> Speed 变化 ±15 对行动频率有约 18% 的影响。Speed 范围推荐: 60~120。

### 3.4 MP 恢复公式

```
每回合恢复 = max(1, maxMP / 5)
```

| maxMP | 每回合恢复 | 放一次12MP技能需等 |
|-------|---|-----|
| 20 (Warrior) | 4 | 3 回合 |
| 35 (Medical) | 7 | 2 回合 |
| 50 | 10 | 2 回合 |

## 六、技能设计基准

### 6.1 技能等级与数值区间

| 技能等级 | Multiplier | FlatBonus | Constant | MP 消耗 | 示例 |
|---------|-----------|-----------|----------|---------|------|
| **普通攻击** | 1.0 | 0 | 0 | 0 | 战士一刀 8*1=8 物伤 |
| **基础技能** | 1.3~1.8 | 0~2 | 0~2 | 10~15 | 重斩: 1.5×, +2 flat → 14 物伤 |
| **强力技能** | 2.0~3.0 | 0~4 | 0~4 | 20~30 | 烈焰斩: 2.5×, +3 flat → 23 物伤 |
| **终极技能** | 3.0~4.0 | 0~5 | 0~5 | 30~40+ | 天降正义: 3.5×, +5 flat → 33 物伤 |
| **治疗技能** | — | — | 6~12 | 12~20 | 治愈: Constant=6, 回复6HP |
| **Buff 技能** | — | BuffID+Stacks | — | 10~20 | 力量术: +3力量, 持续3回合 |
| **AoE 技能** | 0.6~0.8×单体 | 同上 | 同上 | 1.5~2×单体 | 散射箭: 3×3范围, 0.7×伤害 |

### 6.2 技能设计模板

```
技能名: __________
类型: [单体/范围/增益/治疗/移动]
目标: [敌方/友方/自身/位置]
消耗MP: ___
冷却: [无/每X回合/每场战斗N次]

阶段 (可多阶段):
  AoE范围: [SingleTarget/Cross/Diamond/Square]
  效果: [伤害/治疗/加Buff/减Buff/移动施法者]
    公式: (ATK + ___) × ___ + ___ = 预期伤害 ___
    伤害类型: [Physical/Magic/Fire...]
    若为Buff: BuffID=___, 层数=___
```

### 6.3 技能设计原则

1. **NormalAttack 永远是基准线**（1×ATK），其他技能在此之上浮动
2. **有代价才有收益**：更高伤害 = 更高 MP 消耗
3. **AoE 必须降伤害**：覆盖范围每扩大一级，伤害 ×0.7~0.8
4. **治疗量独立于 ATK**：治疗绑在 Constant 上，避免高 ATK 角色成为全能治疗
5. **Buff 层数节制**：单 Buff 通常 1~5 层，Relic 获得渠道另行控制
6. **不同职业的技能方向：**
   - 战士：单体高物伤 + 自强化
   - 弓箭手：远程狙击 + AoE 压制
   - 坦克：嘲讽/护盾 + 低伤 AoE
   - 医者：治疗 + 净化 + 低伤法术

### 6.4 NormalAttack 特殊处理

普通攻击**必须是 SkillDataSO（技能数据）**，类型为 NormalAttack SkillSlot。这样 Buff/Relic 对"普攻"的修饰才能统一通过技能系统作用。

> 重要：NormalAttack 不能是"写死在代码里的单独逻辑"。它应占用第一个技能槽，统一走 SkillExecutor → CombatCalculator 管线。

## 七、Buff 设计指南

### 7.1 已有 Buff 实现

| Buff | 效果 | 层数 | 数值 |
|------|------|------|------|
| **力量 (Strength)** | `OnApply`: ATK +Stacks（Flat） | 1~5 | +1 ATK/层 |
| **虚弱 (Weak)** | `OnApply`: ATK -Stacks（Flat，Debuff） | 1~5 | -1 ATK/层 |
| **狂暴 (Berserk)** | `OnOutgoingDamage`: HP≤50%时，伤害 +Stacks×2 | 1~5 | +2 伤/层 |
| **吸血 (Vampire)** | `OnHit`: 回复 Stacks×1 HP | 1~3 | +1 HP/层 |
| **守护 (Ward)** | `OnIncomingDamage`: 减伤 Stacks×3 | 1~3 | -3 伤/层 |
| **复仇 (Retribution)** | `OnBeHurt`: 反弹 Stacks×1 真伤 | 1~3 | +1 反弹/层 |

### 7.2 Buff 数值基准

| 属性 | 每层效果 | 可叠最大层数 | 设计约束 |
|------|---------|------------|---------|
| ATK | ±1 | 5 | 不得超过角色基准 ATK 的 50% |
| DEF | ±1~2 | 5 | 高 DEF 叠层可能导致物理免疫 |
| RES | ±1 | 5 | 每 2 RES = -1 魔法伤害 |
| SPD | ±5 | 3 | Speed 波动不宜过大 |
| MOV | ±1 | 2 | 移动力是稀有属性 |

### 7.3 Debuff 与 Buff 对称性

| 正面 Buff | 属性 | 负面 Debuff |
|----------|------|-----------|
| Strength +ATK | ATK | Weak -ATK |
| Fortify +DEF | DEF | Sunder -DEF |
| Haste +SPD | SPD | Slow -SPD |
| — | 标记 | Vulnerable（受击伤害 +X） |

> Debuff 通常由精英怪技能施加，数值与对应 Buff 对称。弱化持续 2~3 回合。

## 八、Relic（遗物/藏品）设计指南

### 8.1 稀有度与定价

| 稀有度 | 价格 | 复杂度 | 设计目标 |
|--------|------|--------|---------|
| **Common（普通）** | 50 | 1 个简单效果 | 加属性、小幅增益 |
| **Uncommon（稀有）** | 100 | 1 个有意义效果 | 改变玩法、交互机制 |
| **Rare（罕见）** | 200 | 1~2 个效果 | 显著流派效应 |
| **Epic（史诗）** | 350 | 1 个强效果 + 1 代价 | 高风险高回报 |
| **Legendary（传说）** | 500 | 改变规则 | 每一件都该是 build-around |

### 8.2 Relic 效果设计原则

| 原则 | 说明 |
|------|------|
| **优先定值效果** | "ATK +2" 而非 "ATK +10%" |
| **改变机制 > 堆数值** | "技能击杀敌人时额外获得 1 AP" 好于 "ATK +5" |
| **代价设计** | "ATK +4，但每回合失去 2 HP" 增加决策深度 |
| **稀有度爬升剧烈度** | Common → Rare：线性强化；Epic → Legendary：规则级改变 |

### 8.3 Relic 效果示例

| 稀有度 | 名称 | 效果 |
|--------|------|------|
| Common | 磨刀石 | ATK +1 |
| Common | 皮甲 | DEF +2 |
| Uncommon | 快靴 | SPD +10, MOV +1 |
| Uncommon | 精力药剂 | maxMP +15 |
| Rare | 吸血戒指 | 普攻命中时回复 2 HP（与 Vampire Buff 叠加） |
| Rare | 战术腰包 | 每回合 AP +1（可行动 2 次） |
| Epic | 狂战士护符 | ATK +4，DEF -3 |
| Epic | 幽魂斗篷 | 被攻击时 50% 概率闪避（概率是少数可用百分比的例外） |
| Legendary | 贤者之石 | 每回合开始 MP 回满 |
| Legendary | 时之沙 | 每场战斗可免费使用一次"额外回合" |

## 十、魔法公式改造方案（待办）

### 10.1 当前公式问题

```csharp
// CombatCalculator (Status.cs:371-376)
case DamageType.Magic:
    float resFactor = Mathf.Clamp01(effectiveDefense / 100f);
    finalDamage *= (1.0f - resFactor);
```

- Lv1 角色 RES 只有 2~5，除以 100 后减伤 2%~5%，**几乎无效果**
- 如果要使百分比生效，RES 需要 20~50 范围，与当前小数值体系冲突

### 10.2 改造方案

```csharp
// 新魔法公式
case DamageType.Magic:
    int resDivisor = 2; // 可配置常量
    finalDamage = Mathf.Max(1, finalDamage - effectiveDefense / resDivisor);
    break;
```

- 与物理减法统一，但减损效率为 `RES/2`
- 保底 1 点伤害，魔法不会完全免疫
- RES 范围仍在 0~10+，每 2 点 RES = 减 1 魔法伤害

### 10.3 同时调整的常量

| 常量 | 当前值 | 建议值 | 说明 |
|------|-------|--------|-----|
| `BASE_ACTION_DISTANCE` | 10000 | 保持 | AV 计算基数 |
| `hpGrowthPerLevel` | 1.1 | 移除 | 改用升星表 |
| `atkGrowthPerLevel` | 1.08 | 移除 | 同上 |
| **新增** `MAGIC_RES_DIVISOR` | — | 2 | RES 除数 |

## 十一、战斗回合模型

### 11.1 单场战斗流程预测

| 项目 | 预估值 |
|------|--------|
| 玩家单位 | 5~6 |
| 敌人单位 | 5~8（含 1~2 精英） |
| 回合数（全单位循环） | 5~8 轮 |
| 每人行动次数 | 5~8 次/场 |
| 每人受到攻击 | 2~4 次/场 |
| 单场耐久损耗 | 30%~50% HP |
| 无治疗可撑 | 约 2~3 场战斗 |

### 11.2 全程损耗节奏

```
战斗1 → 损耗30-40%血 → 无恢复 → 战斗2 → 损耗累计50-70% → 无恢复 → 战斗3 → 临界状态
```

> 这意味着：
> 1. **战斗 1-2：** 相对轻松，建立优势
> 2. **战斗 3：** 考验玩家前期资源管理（MP、Buff、战位）
> 3. **Relic 获取：** 在战间商店购买/拾取 Relic 是维持续航的关键
> 4. **治疗角色价值：** 在全程无自动回血的设定下，Medical 可能是队伍必备
